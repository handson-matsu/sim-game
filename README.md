# ラムゼーゲーム（Sim）

6頂点・15辺のグラフで遊ぶ、人間対CPUのWebアプリです。先に自分の色の三角形を作ると負けです。

アプリとテストは `site/` にあります。外部ライブラリ、API、他アプリへの依存はありません。Node.js 20以上で起動できます。

```sh
cd site
npm start
# http://127.0.0.1:4175/

npm test
npm run test:exhaustive
```

`site/dist/` を任意の静的HTTPサーバーで配信しても動作します。ES modulesを使うため、HTMLのファイル直接起動ではなくHTTP経由で開いてください。

## 操作

- グレーの辺をクリック／タップして着色。両端の頂点を順に選択する操作にも対応。
- Tabで辺・頂点へ移動し、Enter / Spaceで決定。
- 先手／後手を選択。「もう一度」「先手／後手を入れ替える」は対戦途中でも利用可能。
- CPUは800ms後に着手し、その間は人間の入力を受け付けません。リセット時は予約中の着手を取り消します。
- 青の実線が人間、赤の破線がCPU。敗北を決めた三角形は3辺を太く強調します。

## CPU戦略

[Wrzos-Kaminska, A simpler winning strategy for Sim (2020)](https://arxiv.org/abs/2001.04024) のRule 1 → 2 → 3を階層的に適用します。

1. mini-board上でCPU自身の単色三角形を作らない未使用辺のみを残す。
2. 辺数最大のCPU-allowed setをすべて求め、含まれる集合数が最大の辺だけを残す。
3. 残った辺について、辺数最大のHUMAN-allowed setに含まれる集合数が最大の辺だけを残す。
4. 最終候補が複数なら一様ランダム選択。

mini-boardは6頂点の64部分集合から完全部分グラフを作り、着色済み全辺とCPUのallowed moveを含むもののうち、条件を満たす真部分集合を持たないものを求めます。実際の対戦では列挙順の最初の1つを選びます。

maximum allowed setは、mini-boardの未使用辺から個別にも危険な辺を除き、その全部分集合を列挙します。現在の所有辺と集合全体の和に三角形がないことを判定し、辺数が最大の集合をすべて保存します。包含極大とは区別しています。

15ビットの辺集合を使用しています。事前計算しているのは辺数と単色三角形の有無だけです。勝敗データベース、minimax、ゲーム木探索による着手選択は使用しません。ゲーム木探索はテスト専用ファイルに分離され、配信フォルダーにも含まれません。

## 論文との相違点

後手CPUの戦略に変更はありません。要件どおり、CPU先手もCPU=P2・人間=P1として同じ評価を使う実験モードです。先手初手だけは全15辺からランダム選択します。`paper-second` / `experimental-first` で内部的にも区別し、先手の必勝保証は表示しません。安全手がない場合は未使用辺に実際に着色し、通常の敗北判定を行います。

## 検証結果

- 自動テスト14件成功。32,768通りの単色グラフを独立の隣接行列判定と照合。
- 120局面で最大allowed setを独立の再帰列挙と照合。Rule 2よりRule 3が優先されないことや、両段階で実際に候補が絞られることも検証。
- 後手CPU全探索：**300,598の非終端局面**（頂点ラベルを区別、同一局面はメモ化）を検証。CPUの敗北は**0**。
- 人間の着手分岐655,155、CPUの着手分岐273,000。人間の即時敗北分岐305,100。
- CPU同点候補を持つ局面73,965、調べたmini-boardは182,310。
- 人間初手15本すべて、人間の危険手を含む全着手、Rule 3後の候補すべて、さらに選択可能なmini-boardすべてについて分岐。ランダムなサンプリングは使用しません。
- 局面数は初期局面を含む非終端の一意な局面数です。終端は着手分岐数として別集計。手順の順序が異なっても同じ盤面なら再利用します。
- 実ブラウザー：CPU応答、使用済み辺の拒否、2頂点選択、先後交代、390pxスマートフォン幅・768pxタブレット幅での横はみ出しなしを確認。

機械可読な結果は `site/tests/exhaustive-result.json` に保存しています。

## ファイル

- `site/dist/index.html`, `style.css`, `app.js`: 日本語UI・SVG盤面
- `site/dist/strategy.js`: 論文の着手戦略
- `site/dist/game.js`: 手番、タイマー、勝敗処理
- `site/tests/*.test.mjs`: 単体・回帰テスト
- `site/tests/exhaustive.mjs`: 後手CPU全探索検証（対戦時は未使用）
